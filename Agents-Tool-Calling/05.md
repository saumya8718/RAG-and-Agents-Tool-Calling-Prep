# 05. Multi-Agent Systems

## 1. What is a multi-agent system?

### Answer

A **multi-agent system** is an architecture where **multiple AI agents work together** to accomplish a larger task.

Instead of having one agent perform every task, different agents can be given different responsibilities.

For example:

```text
                User
                  ↓
            Main / Manager Agent
                  ↓
        ┌─────────┼─────────┐
        ↓         ↓         ↓
   Researcher   Analyst   Writer
     Agent       Agent     Agent
        ↓         ↓         ↓
        └─────────┼─────────┘
                  ↓
            Final Response
```

Each agent can have:

- Its own instructions
- Its own tools
- A specific responsibility
- Access to shared or task-specific state

### Example

Suppose the task is:

> "Research a company and prepare a report."

Different agents could handle:

```text
Research Agent
→ Collect information

Analysis Agent
→ Analyze the information

Writing Agent
→ Prepare the report
```

A coordinating agent can combine their results.

### Single Agent vs Multi-Agent

Single agent:

```text
User
 ↓
Agent
 ↓
Tools
 ↓
Answer
```

Multi-agent:

```text
User
 ↓
Manager Agent
 ↓
┌───────────────┐
│               │
Researcher   Analyst
│               │
└───────┬───────┘
        ↓
   Writer Agent
        ↓
     Answer
```

### Key Point

> **A multi-agent system uses multiple specialized AI agents that collaborate or coordinate to solve a task.**

### Interview Answer

> **A multi-agent system is an architecture where multiple AI agents work together on a task. Each agent can have a specialized role, such as research, analysis, or writing, and a coordinating mechanism combines their results to accomplish the overall goal.**

## 2. When would you use multiple agents instead of one agent?

### Answer

Multiple agents can be useful when a problem contains **clearly separable tasks that require different responsibilities, tools, or expertise**.

### 1. Different Specialized Tasks

For example:

```text
Research
Analysis
Writing
```

Instead of making one agent handle everything:

```text
Manager
 ├── Research Agent
 ├── Analysis Agent
 └── Writing Agent
```

---

### 2. Different Tools or Capabilities

Different agents may have access to different tools.

```text
Research Agent
→ Web Search

Database Agent
→ SQL Database

Calculation Agent
→ Calculator

Writing Agent
→ Document Tools
```

This can make responsibilities clearer.

---

### 3. Complex Tasks

A large task can be divided into smaller subtasks.

Example:

> "Analyze a company's financial performance and prepare a report."

Possible decomposition:

```text
Collect Data
     ↓
Financial Analysis
     ↓
Compare Results
     ↓
Generate Report
```

Different agents can handle these stages.

---

### 4. Parallel Work

Some tasks can be performed independently.

For example:

```text
                 Manager
                /       \
               ↓         ↓
        Market Research  Competitor Research
               ↓         ↓
                \       /
                 ↓     ↓
                 Analyst
```

The research tasks can potentially run in parallel.

---

### When One Agent Is Better

Do not automatically use multiple agents.

If the task is:

```text
Simple
+
Small
+
Uses few tools
+
Has a straightforward flow
```

one agent or even a normal workflow may be sufficient.

### Decision Rule

```text
Simple task
    ↓
One agent / workflow

Complex task
    ↓
Clearly separable subtasks
    ↓
Multiple specialized agents
```

### Key Point

> **Use multiple agents when the task can be meaningfully divided into specialized, independent, or complex subtasks. Do not use multiple agents simply because the problem is large.**

### Interview Answer

> **I would use multiple agents when a task contains clearly separable subtasks that benefit from specialization, different tools, or parallel execution. For a simple or predictable task, one agent or a deterministic workflow is usually sufficient because multiple agents add communication and coordination overhead.**


---

## 3. How can multiple agents communicate with each other?

### Answer

Multiple agents can communicate by **passing structured messages, task results, or shared state** between them.

The communication mechanism depends on the architecture.

### 1. Direct Message Passing

One agent sends the result directly to another.

```text
Research Agent
      ↓
Research Result
      ↓
Analysis Agent
```

Example:

```text
Research Agent:
{
    "company": "ABC",
    "revenue": 100,
    "growth": 15
}
        ↓
Analysis Agent
```

The second agent uses this information for analysis.

---

### 2. Shared State

Multiple agents can read and update a shared state.

```text
             Shared State
            /      |      \
           ↓       ↓       ↓
      Research  Analysis  Writer
       Agent     Agent     Agent
```

For example:

```text
state = {
    "research": "...",
    "analysis": "...",
    "final_report": null
}
```

The research agent updates `research`, and the analysis agent reads it.

---

### 3. Message Queue

For larger systems, agents can communicate through a messaging system.

```text
Agent A
   ↓
Message Queue
   ↓
Agent B
```

This can help when agents operate independently or asynchronously.

---

### 4. Orchestrator / Manager

A central agent can coordinate communication.

```text
             Manager
            /       \
           ↓         ↓
     Researcher   Analyst
           \         /
            ↓       ↓
             Manager
```

The manager receives results and decides what should happen next.

### Structured Communication

It is generally useful to exchange structured information:

~~~json
{
  "task": "analyze_company",
  "status": "completed",
  "data": {
    "revenue_growth": 15
  }
}
~~~

This is easier to validate and process than unrestricted natural-language messages.

### Key Point

> **Agents can communicate through direct messages, shared state, message queues, or a central orchestrator, with structured data often used to make communication reliable.**

### Interview Answer

> **Multiple agents can communicate by passing messages or structured results directly, using shared state, or communicating through a central orchestrator or message queue. In production systems, structured messages are useful because they make the communication easier to validate, process, and debug.**

## 4. What are the advantages and problems of multi-agent architectures?

### Answer

Multi-agent architectures can provide **specialization and modularity**, but they also introduce additional complexity.

### Advantages

#### 1. Specialization

Each agent can focus on a specific responsibility.

```text
Research Agent → Research
Database Agent → Data
Writer Agent → Writing
```

This can make the system easier to design around distinct tasks.

---

#### 2. Parallel Execution

Independent tasks can potentially run at the same time.

```text
             Manager
             /     \
            ↓       ↓
       Research A  Research B
            ↓       ↓
             \     /
              ↓   ↓
             Result
```

This can reduce total execution time when the architecture supports parallel execution.

---

#### 3. Modularity

Each agent can be developed and tested separately.

```text
Research Agent
      +
Analysis Agent
      +
Writing Agent
```

Changing one agent may not require redesigning the entire system.

---

#### 4. Different Tools and Responsibilities

Agents can have different tool access.

```text
Research Agent → Search
Database Agent → SQL
Calculator Agent → Math
```

This can also make permissions easier to separate.

---

### Problems

#### 1. Increased Complexity

Instead of:

```text
User → Agent → Tool
```

you may have:

```text
User
 ↓
Manager
 ↓
Agent A
 ↓
Agent B
 ↓
Agent C
```

More components mean more things that can fail.

---

#### 2. Communication Overhead

Agents need to exchange information.

```text
Agent A
 ↓
Message
 ↓
Agent B
```

These additional interactions can increase latency and token usage.

---

#### 3. Coordination Problems

Agents may:

- Duplicate work
- Produce conflicting results
- Fail to agree on information
- Depend on unavailable results
- Pass incomplete information

---

#### 4. Higher Cost

Each agent may involve multiple LLM calls.

```text
Manager LLM
    ↓
Research LLM
    ↓
Analysis LLM
    ↓
Writing LLM
```

More model calls can increase cost.

---

#### 5. More Difficult Debugging

It becomes harder to determine where a failure occurred.

```text
Manager
  ↓
Research Agent
  ↓
Analysis Agent
  ↓
Writer
```

A wrong final answer could originate from any stage.

---

#### 6. Security and Permission Risks

Giving multiple agents access to tools increases the number of components that need proper authorization and guardrails.

### Comparison

| Advantages | Problems |
|---|---|
| Specialization | Increased complexity |
| Modularity | Communication overhead |
| Parallel execution | Coordination problems |
| Different tool access | Higher cost |
| Easier separation of responsibilities | More difficult debugging |
| Can handle complex tasks | More security considerations |

### Key Point

> **Multi-agent systems can improve specialization, modularity, and parallelism, but they also introduce coordination, communication, cost, debugging, and security challenges.**

### Interview Answer

> **The main advantages of multi-agent architectures are specialization, modularity, separation of responsibilities, and potential parallel execution. The main problems are increased complexity, communication overhead, higher cost and latency, coordination failures, difficult debugging, and additional security considerations.**


---

## 5. How would you design a system where one agent delegates tasks to specialized agents?

### Answer

A common design is to use a **manager/orchestrator agent** that understands the overall goal and delegates specific subtasks to specialized agents.

### Example

Suppose the user asks:

> "Research a company, analyze its competitors, and prepare a report."

We can create:

```text
                 User
                  ↓
          Manager Agent
                  ↓
       ┌──────────┼──────────┐
       ↓          ↓          ↓
 Researcher   Competitor   Data
   Agent        Agent      Analyst
       ↓          ↓          ↓
       └──────────┼──────────┘
                  ↓
          Manager Agent
                  ↓
            Writer Agent
                  ↓
             Final Report
```

### Step 1: Manager Receives the Goal

```text
Goal:
"Research company ABC and prepare a report."
```

The manager identifies the required subtasks.

```text
Subtasks:
1. Research company
2. Research competitors
3. Analyze data
4. Write report
```

### Step 2: Manager Delegates

The manager sends tasks to specialized agents.

```text
Manager
  ├──→ Research Agent
  │       └── Company information
  │
  ├──→ Competitor Agent
  │       └── Competitor information
  │
  └──→ Data Analyst
          └── Analysis
```

### Step 3: Specialized Agents Execute

Each agent uses its own instructions and tools.

```text
Research Agent
→ Search tools

Competitor Agent
→ Search / database tools

Data Analyst
→ Calculator / data tools
```

### Step 4: Results Are Returned

Each agent sends a structured result back to the manager.

For example:

~~~json
{
  "agent": "research_agent",
  "status": "completed",
  "result": {
    "revenue": 100,
    "employees": 5000
  }
}
~~~

### Step 5: Manager Combines Results

```text
Research Result
       +
Competitor Result
       +
Analysis Result
       ↓
Manager
```

The manager checks whether enough information is available.

If something is missing:

```text
Manager
   ↓
Delegate another task
   ↓
Specialized Agent
   ↓
Result
```

### Step 6: Generate Final Output

Once all required subtasks are completed:

```text
Manager
   ↓
Combine Results
   ↓
Final Answer / Report
```

### Important Design Components

A practical system should have:

#### 1. Manager Agent

Responsible for:

- Understanding the overall goal
- Breaking it into subtasks
- Assigning tasks
- Tracking progress
- Combining results

#### 2. Specialized Agents

Each handles one responsibility.

```text
Research Agent
Analysis Agent
Writing Agent
Database Agent
```

#### 3. Shared State / Task State

Tracks:

```text
Task status
Agent results
Pending tasks
Completed tasks
Errors
```

#### 4. Communication Protocol

Define how agents exchange information.

For example:

~~~json
{
  "task_id": "T101",
  "status": "completed",
  "result": "..."
}
~~~

#### 5. Limits and Guardrails

Use:

- Maximum delegation depth
- Maximum number of agents/tasks
- Timeouts
- Tool permissions
- Input/output validation
- Error handling

### Simple Architecture

```text
                       User
                        ↓
                ┌──────────────┐
                │ Manager Agent│
                └───────┬──────┘
                        ↓
                 Task Decomposition
                        ↓
          ┌─────────────┼─────────────┐
          ↓             ↓             ↓
    Research Agent  Analyst Agent  Writer Agent
          ↓             ↓             ↓
          └─────────────┼─────────────┘
                        ↓
                  Shared State
                        ↓
                Manager Agent
                        ↓
                  Final Answer
```

### Key Point

> **A manager agent can decompose the user's goal into subtasks, delegate each subtask to a specialized agent, collect their results through structured communication/shared state, and combine the results into the final response.**

### Interview Answer

> **I would design a manager-worker architecture. A manager agent receives the overall goal, breaks it into subtasks, and delegates them to specialized agents such as research, analysis, or writing agents. Each specialized agent performs its task using its available tools and returns a structured result. The manager tracks the shared state, handles failures or missing information, combines the results, and produces the final response. I would also add limits, timeouts, validation, and appropriate permissions to prevent uncontrolled delegation.**
