# 01. Agent Fundamentals

## 1. What is an AI Agent?

### Answer

An **AI agent** is a system that uses an LLM to understand a goal, decide what actions are needed, use available tools, observe the results, and continue taking actions until the task is completed.

Unlike a simple LLM application that usually follows a fixed flow, an agent can **dynamically decide what to do next** based on the current situation.

### Basic Agent Flow

~~~text
User Goal
    ↓
    LLM
    ↓
Decide Next Action
    ↓
 ┌───────────────┐
 │ Need a tool?  │
 └───────┬───────┘
       Yes
        ↓
   Call Tool
        ↓
   Tool Result
        ↓
      LLM
        ↓
Decide Next Action
        ↓
     Repeat
        ↓
 Final Answer
~~~

### Main Idea

An agent typically follows a loop:

```text
Understand → Decide → Act → Observe → Decide Again
```

For example, suppose the user asks:

> "What is the weather in Delhi and should I carry an umbrella?"

The agent could:

```text
User Question
      ↓
Understand request
      ↓
Call Weather Tool
      ↓
Receive weather data
      ↓
Analyze the result
      ↓
Generate final answer
```

For a more complex task, the agent may need multiple actions:

```text
User Goal
    ↓
Search Information
    ↓
Analyze Results
    ↓
Call Another Tool
    ↓
Combine Results
    ↓
Final Answer
```

### Main Components of an AI Agent

An agent generally consists of:

1. **LLM / Reasoning Model**
   - Understands the user's request.
   - Decides what action should be taken.

2. **Tools**
   - Allow the agent to interact with external systems.
   - Examples:
     - Search
     - Calculator
     - Database
     - APIs
     - Code execution

3. **State / Memory**
   - Keeps track of information needed across multiple steps.

4. **Agent Loop**
   - Repeatedly decides, acts, observes the result, and decides what to do next.

5. **Instructions / Goals**
   - Define what the agent should accomplish and how it should behave.

### Agent vs Simple LLM Application

A simple LLM application may look like:

~~~text
User
 ↓
Prompt
 ↓
LLM
 ↓
Response
~~~

An agent can look like:

~~~text
User
 ↓
LLM
 ↓
Choose Action
 ↓
Tool
 ↓
Observe Result
 ↓
LLM
 ↓
Choose Next Action
 ↓
...
 ↓
Final Response
~~~

The key difference is that an agent can **dynamically choose actions and perform multiple steps** instead of only generating a response from a fixed prompt.

### Example

Suppose the user asks:

> "Find the price of a product and calculate the total cost for 3 units."

An agent could:

```text
1. Understand the task
        ↓
2. Use a product/API tool
        ↓
3. Get the product price
        ↓
4. Use a calculator tool
        ↓
5. Calculate price × 3
        ↓
6. Return the result
```

The important part is that the agent determines which actions are required instead of the application having to hard-code every step.

### Important Point

An AI agent is **not simply an LLM**.

The LLM is usually the decision-making component, while the complete agent system includes:

```text
LLM
 +
Tools
 +
State/Memory
 +
Instructions
 +
Agent Loop
```

### Key Point

> **An AI agent is an LLM-powered system that can decide what actions to take, use tools, observe their results, and perform multiple steps to achieve a goal.**

### Interview Answer

> **An AI agent is a system that uses an LLM to understand a user's goal and dynamically decide what actions are required to achieve it. It can use external tools such as APIs, databases, search engines, or calculators, observe the results, and continue taking actions until the task is completed. The basic agent loop is **understand → decide → act → observe → decide again → final answer**. The important difference from a simple LLM application is that the agent can dynamically choose and execute actions rather than following only a fixed sequence.**


## 2. How is an AI agent different from a traditional LLM application?

### Answer

A **traditional LLM application** usually follows a **fixed workflow** where the developer decides the steps in advance.

An **AI agent** can dynamically decide **what action to take next** based on the user's goal and the results of previous actions.

### Traditional LLM Application

```text
User
  ↓
Prompt
  ↓
LLM
  ↓
Response
```

The flow is mostly predetermined.

For example:

```text
User Question
      ↓
Retrieve Documents
      ↓
Send Context to LLM
      ↓
Generate Answer
```

The application follows the same general sequence for every request.

### AI Agent

```text
User Goal
    ↓
   LLM
    ↓
Decide Next Action
    ↓
Use Tool
    ↓
Observe Result
    ↓
   LLM
    ↓
Decide Next Action
    ↓
   ...
    ↓
Final Answer
```

The agent can decide whether it needs to:

- Search the web
- Call an API
- Query a database
- Use a calculator
- Retrieve documents
- Call another tool
- Stop and provide the answer

### Example

Suppose the user asks:

> "Find the current price of a product and calculate the total cost for 5 units."

A traditional application might have a fixed pipeline:

```text
Input
 ↓
Product API
 ↓
Calculator
 ↓
Response
```

An agent can dynamically determine:

```text
Understand request
       ↓
Need product price?
       ↓
Call Product API
       ↓
Get price
       ↓
Need calculation?
       ↓
Call Calculator
       ↓
Return result
```

### Key Difference

| Traditional LLM Application | AI Agent |
|---|---|
| Mostly predefined flow | Dynamically chooses actions |
| Usually fewer decision points | Multiple decision points |
| LLM mainly generates/understands text | LLM can reason about what action to take |
| Tools may be explicitly called by code | Agent can select tools |
| Usually predictable execution | More flexible but less predictable |

### Key Point

> **Traditional LLM applications follow a predefined workflow, while AI agents can dynamically decide which actions or tools to use to accomplish a goal.**

### Interview Answer

> **An AI agent differs from a traditional LLM application because an agent can dynamically decide what action to take based on the task and the results it observes. A traditional LLM application generally follows a predefined pipeline, whereas an agent can select tools, execute multiple steps, observe their results, and continue until the task is completed.**

## 3. What are the main components of an AI agent?

### Answer

An AI agent is not just an LLM. It is a system consisting of several components that work together.

The main components are:

1. **LLM / Reasoning Model**
2. **Tools**
3. **Instructions / Goal**
4. **State / Memory**
5. **Agent Loop**

### 1. LLM / Reasoning Model

The LLM is responsible for understanding the user's request and deciding what should happen next.

For example:

```text
User: "What is the weather in Delhi?"

LLM:
"I need to use the weather tool."
```

---

### 2. Tools

Tools allow the agent to interact with external systems.

Examples:

- Web search
- Calculator
- Database
- Weather API
- Payment API
- File system
- RAG retrieval system

```text
LLM
 ↓
Tool Selection
 ↓
Weather API
 ↓
Weather Result
```

---

### 3. Instructions / Goal

The agent needs instructions that define:

- What it should do
- What it should not do
- Which tools it can use
- How it should respond

For example:

```text
You are a shopping assistant.
Use the product search tool when the user asks
for current product information.
```

---

### 4. State / Memory

State allows the agent to keep track of what has happened during execution.

For example:

```text
User request
      ↓
Tool 1 result
      ↓
Tool 2 result
      ↓
Current state
```

Memory can also help maintain relevant information across interactions.

---

### 5. Agent Loop

The agent loop allows the agent to repeatedly:

```text
Understand
   ↓
Decide
   ↓
Act
   ↓
Observe
   ↓
Decide again
```

The loop continues until the agent determines that the task is complete.

### Overall Architecture

```text
                 ┌──────────────┐
                 │ User / Goal  │
                 └──────┬───────┘
                        ↓
                 ┌──────────────┐
                 │     LLM      │
                 └──────┬───────┘
                        ↓
                 Decide Action
                        ↓
              ┌─────────┴─────────┐
              ↓                   ↓
            Tool              Final Answer
              ↓
         Tool Result
              ↓
            State
              ↓
             LLM
              ↓
        Decide Again
```

### Key Point

> **An AI agent consists of an LLM, instructions/goals, tools, state or memory, and an agent loop that coordinates repeated decision-making and actions.**

### Interview Answer

> **The main components of an AI agent are the LLM or reasoning model, tools, instructions or goals, state or memory, and the agent loop. The LLM decides what to do, tools allow the agent to interact with external systems, state maintains relevant information, and the agent loop coordinates multiple actions until the task is completed.**

## 4. How does an agent decide what action to take?

### Answer

An agent generally uses the **LLM as the decision-making component**.

The LLM receives:

- User request
- System instructions
- Available tools
- Tool descriptions/schemas
- Current state
- Results from previous actions

It then determines whether it should:

1. Answer directly
2. Call a tool
3. Call another tool
4. Continue the task
5. Stop and return the final answer

### Example

User asks:

> "What is the weather in Delhi?"

The agent may reason about the available options:

```text
User Request
     ↓
   Agent
     ↓
Does this require external information?
     ↓
    Yes
     ↓
Select weather tool
     ↓
Call weather API
     ↓
Receive result
     ↓
Generate final answer
```

If the user asks:

> "What is 25 × 4?"

The agent may decide:

```text
User Request
     ↓
   Agent
     ↓
Can I answer directly?
     ↓
    Yes
     ↓
Return answer
```

### Tool Selection

Suppose an agent has:

```text
Tools:
1. search_web()
2. calculator()
3. get_weather()
4. query_database()
```

For:

> "Calculate 125 × 48"

the LLM may select:

```text
calculator()
```

For:

> "What is today's weather?"

it may select:

```text
get_weather()
```

For:

> "Find the latest information about RAG."

it may select:

```text
search_web()
```

### What Does the LLM Consider?

The decision can depend on:

- User's goal
- Tool descriptions
- Tool input requirements
- Current state
- Previous tool results
- System instructions
- Whether external information is required

### Important Point

The LLM **does not directly execute the tool**.

Instead:

```text
LLM
 ↓
Select tool
 ↓
Generate structured arguments
 ↓
Application validates/execut es tool
 ↓
Tool result
 ↓
LLM
```

### Key Point

> **The agent uses the LLM to select the next action based on the user's goal, available tools, instructions, current state, and previous results.**

### Interview Answer

> **An agent decides what action to take using an LLM as its decision-making component. The LLM considers the user's goal, available tools, tool descriptions, instructions, current state, and previous results. It can decide to answer directly, call a tool, perform another step, or stop when the task is complete.**

## 5. What is the difference between an LLM, workflow, and agent?

### Answer

The three concepts can be understood by looking at **who controls the next step**.

### 1. LLM

An **LLM** primarily takes an input and generates an output.

```text
Input
  ↓
 LLM
  ↓
Output
```

Example:

```text
User:
"Explain RAG."

        ↓

LLM

        ↓

"RAG stands for Retrieval-Augmented Generation..."
```

The LLM itself does not automatically execute external tools.

---

### 2. Workflow

A **workflow** is a predefined sequence of steps.

```text
Input
 ↓
Step 1
 ↓
Step 2
 ↓
Step 3
 ↓
Output
```

For example, a fixed RAG workflow:

```text
Question
   ↓
Create Embedding
   ↓
Search Vector DB
   ↓
Retrieve Documents
   ↓
Send Context to LLM
   ↓
Answer
```

The developer defines the sequence.

---

### 3. Agent

An **agent** can dynamically decide what to do next.

```text
Goal
 ↓
LLM
 ↓
Choose Action
 ↓
Tool
 ↓
Observe Result
 ↓
LLM
 ↓
Choose Next Action
 ↓
...
 ↓
Final Answer
```

The exact path can change depending on the task.

### Comparison

| LLM | Workflow | Agent |
|---|---|---|
| Generates output | Executes predefined steps | Dynamically chooses steps |
| Usually one main generation step | Fixed sequence | Flexible sequence |
| Does not inherently manage tools | Code controls tools | LLM can select tools |
| Simple | Predictable | More flexible |
| Limited decision-making | Developer-defined decisions | Model-driven decisions |

### Simple Example

Task:

> "Research a company and summarize its recent products."

**LLM:**

```text
Question → LLM → Answer
```

It may not have access to current information.

**Workflow:**

```text
Search company
     ↓
Retrieve information
     ↓
Summarize
```

The steps are predetermined.

**Agent:**

```text
Goal
 ↓
Agent decides to search
 ↓
Search result
 ↓
Agent decides another search is needed
 ↓
Search again
 ↓
Agent summarizes
```

### Key Point

> **LLM generates, workflow follows predefined steps, and an agent dynamically chooses actions to accomplish a goal.**

### Interview Answer

> **An LLM is primarily a model that understands input and generates output. A workflow is a predefined sequence of operations controlled by the application. An agent is a system where the LLM can dynamically choose actions, use tools, observe results, and continue through multiple steps to achieve a goal.**

## 6. When should you use an agent instead of a normal LLM pipeline?

### Answer

An agent is useful when the task requires **dynamic decision-making, multiple steps, or tool usage**.

You should consider an agent when:

### 1. The next step is not always known

If the application needs to decide what to do based on previous results:

```text
Result 1
   ↓
Decide next action
   ↓
Result 2
   ↓
Decide next action
```

An agent can be useful.

---

### 2. Multiple tools may be required

For example:

```text
Search API
    ↓
Database
    ↓
Calculator
    ↓
RAG
```

The agent can decide which tools are required for a particular request.

---

### 3. The task is multi-step

Example:

> "Research three companies, compare their products, calculate their average price, and summarize the result."

Possible steps:

```text
Search
 ↓
Retrieve information
 ↓
Extract data
 ↓
Calculate
 ↓
Compare
 ↓
Summarize
```

The required actions may vary depending on the information found.

---

### 4. The environment is dynamic

If the agent needs to react to tool results:

```text
Call API
   ↓
Check result
   ↓
If incomplete → another action
   ↓
If complete → final answer
```

An agent can handle this dynamic behavior.

---

### When NOT to Use an Agent

If the task has a simple and predictable sequence, a normal workflow is often more appropriate.

For example:

```text
Input
 ↓
Validate
 ↓
Database Query
 ↓
Format Result
 ↓
Output
```

There is no need for an LLM to dynamically decide every step.

### Decision Rule

```text
Simple + predictable
        ↓
     Workflow

Dynamic + multi-step + tool selection
        ↓
       Agent
```

### Important Trade-off

Agents provide flexibility, but they also introduce:

- More complexity
- Less predictable execution
- More latency
- More token usage
- More opportunities for errors

Therefore, **not every problem needs an agent**.

### Key Point

> **Use an agent when the task requires dynamic decisions, multiple tools, or multi-step execution. Use a normal workflow when the steps are known and predictable.**

### Interview Answer

> **I would use an agent when the task is dynamic, multi-step, or requires the system to choose among multiple tools based on intermediate results. If the process is simple and deterministic, I would prefer a normal LLM pipeline or workflow because it is easier to control, test, and debug.**

## 7. What are the major limitations and failure modes of AI agents?

### Answer

AI agents are flexible, but their dynamic behavior introduces several failure modes.

The major ones are:

### 1. Wrong Tool Selection

The agent may select the wrong tool.

```text
User Request
     ↓
LLM
     ↓
Wrong Tool
     ↓
Wrong Result
```

For example, it may use a search tool when a database query was required.

---

### 2. Invalid Tool Arguments

The LLM may generate arguments that do not match the tool schema.

Example:

```json
{
  "city": 123
}
```

when the tool expects:

```json
{
  "city": "Delhi"
}
```

Therefore, tool arguments should be validated before execution.

---

### 3. Hallucination

An agent can generate information that is not supported by the available evidence or tool results.

This can happen during:

- Planning
- Tool selection
- Interpretation of results
- Final answer generation

---

### 4. Infinite or Excessive Loops

An agent may repeatedly perform actions without reaching a useful conclusion.

```text
LLM
 ↓
Tool
 ↓
LLM
 ↓
Tool
 ↓
LLM
 ↓
Tool
 ↓
...
```

This can increase:

- Latency
- Token usage
- Cost
- Resource consumption

A maximum step limit should therefore be used.

---

### 5. Poor Planning

The agent may choose an inefficient sequence of actions.

For example:

```text
Search → Search → Search → Search
```

when one well-designed search could have been enough.

---

### 6. Tool Failures

External tools can fail because of:

- API errors
- Network problems
- Timeouts
- Rate limits
- Invalid responses
- Service unavailability

The agent must handle these failures safely.

---

### 7. Untrusted Tool Output

Tool results should not automatically be treated as trusted instructions.

For example:

```text
External Website
      ↓
Malicious / misleading content
      ↓
Tool Output
      ↓
Agent
```

This can contribute to **prompt injection** or unsafe behavior.

---

### 8. Unauthorized Actions

If an agent has access to powerful tools, it may perform an action that the user or system did not intend.

Examples:

- Modifying a database
- Sending an email
- Making a purchase
- Calling a sensitive API

Therefore, permissions and authorization checks are important.

---

### 9. High Cost and Latency

Multiple LLM calls and tool calls can make an agent slower and more expensive than a simple pipeline.

```text
LLM Call
 ↓
Tool
 ↓
LLM Call
 ↓
Tool
 ↓
LLM Call
```

Every additional step can add latency and cost.

---

### 10. Difficult Debugging

A fixed pipeline is relatively easy to trace:

```text
A → B → C → D
```

An agent may take different paths:

```text
A → B → D
A → C → E → D
A → B → C → E
```

This makes debugging and testing more difficult.

### Major Failure Categories

| Failure | Example |
|---|---|
| Wrong tool selection | Chooses search instead of database |
| Invalid arguments | Wrong parameter type |
| Hallucination | Invented information |
| Infinite loop | Repeated tool calls |
| Poor planning | Unnecessary actions |
| Tool failure | API timeout |
| Prompt injection | Malicious tool/web content |
| Unauthorized action | Unsafe database/API operation |
| High cost | Too many LLM/tool calls |
| High latency | Long multi-step execution |
| Debugging difficulty | Unpredictable execution path |

### How to Reduce These Problems

Use:

- Tool schemas
- Input validation
- Output validation
- Authentication and authorization
- Maximum step limits
- Timeouts
- Retries with limits
- Logging and tracing
- Guardrails
- Human approval for sensitive actions
- Monitoring and evaluation

### Key Point

> **The flexibility of agents is also their main source of risk. They can select the wrong tools, generate invalid arguments, loop indefinitely, encounter tool failures, consume excessive resources, or perform unsafe actions.**

### Interview Answer

> **The major limitations of AI agents are unpredictability, incorrect tool selection, invalid tool arguments, hallucinations, infinite loops, tool failures, security risks such as prompt injection, unauthorized actions, high latency and cost, and difficult debugging. These problems can be reduced using validation, permissions, guardrails, step limits, timeouts, retries, logging, monitoring, and human approval for sensitive operations.**
