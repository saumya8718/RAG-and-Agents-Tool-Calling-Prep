# 04. Memory & State

## 1. What is memory in an AI agent?

### Answer

**Memory** in an AI agent is the mechanism used to retain and retrieve information that is useful for the agent's current or future tasks.

Memory allows an agent to avoid treating every interaction as completely independent.

For example:

```text
User:
"My name is Rahul."

        ↓

Agent stores relevant information

        ↓

Later:

User:
"What is my name?"

        ↓

Agent retrieves:
"Rahul"
```

However, **memory is not simply the entire conversation history**.

A proper memory system decides:

- What information is worth keeping
- Where it should be stored
- When it should be retrieved
- What information should be included in the current context

### Memory vs Context

```text
Memory
  ↓
Stored information
  ↓
Retrieve relevant information
  ↓
Current Context
  ↓
LLM
```

The agent does not need to send every piece of historical information to the LLM.

### Examples of Information Stored in Memory

Depending on the application, memory could contain:

- Previous user preferences
- Important facts from earlier interactions
- Previous task results
- User-specific information
- Long-running task information
- Relevant past interactions

### Memory in an Agent

```text
             ┌─────────────┐
             │    Agent    │
             └──────┬──────┘
                    │
              Read / Write
                    ↓
             ┌─────────────┐
             │   Memory    │
             └─────────────┘
```

### Key Point

> **Memory is a mechanism for storing and retrieving useful information across interactions or tasks. It is not simply the complete chat history copied into every prompt.**

### Interview Answer

> **Memory in an AI agent is the mechanism used to retain and retrieve relevant information that may be useful later. It can store things such as previous task results, user preferences, or important facts. A good memory system selects relevant information rather than blindly passing the entire conversation history to the LLM.**

## 2. Why does an agent need state?

### Answer

**State** represents the agent's current situation and information needed to continue execution correctly.

An agent performing a multi-step task needs to know what has already happened.

For example:

```text
User Goal:
"Find a laptop and calculate its price after discount."

Step 1:
Laptop found
Price = ₹50,000

Step 2:
Discount = 10%

Current State:
Price = ₹50,000
Discount = 10%
Laptop = Selected
```

Without state, the agent may not know what information was already obtained.

### State During an Agent Loop

```text
User Goal
   ↓
State
   ↓
Tool 1
   ↓
Update State
   ↓
Tool 2
   ↓
Update State
   ↓
Final Answer
```

### What Can State Contain?

State may contain:

- User request
- Current task status
- Tool results
- Intermediate data
- Current plan
- Errors
- Previous actions
- Information required for the next step

### Example

Suppose an agent is booking a flight:

```text
State:

destination = Delhi
date = 10 October
flight_selected = AI-302
payment_status = pending
```

After payment:

```text
payment_status = successful
```

The agent can now continue to the next step.

### State vs Memory

A useful distinction is:

```text
State
→ What the agent needs to know about the CURRENT task.

Memory
→ Information that may be useful across interactions or FUTURE tasks.
```

For example:

```text
Current task:
Selected flight = AI-302
        ↓
State

User prefers window seats
        ↓
Memory
```

### Key Point

> **An agent needs state to keep track of the current task, intermediate results, previous actions, and what should happen next.**

### Interview Answer

> **State represents the information an agent needs during its current execution. It can contain the user's goal, previous tool results, intermediate data, current progress, errors, and other information required for the next step. Without state, an agent would have difficulty coordinating multiple steps and tool calls.**

## 3. What is the difference between conversation history and agent memory?

### Answer

**Conversation history** is the record of messages exchanged in a conversation.

**Agent memory** is a system that stores and retrieves information considered useful for future tasks or interactions.

They are related, but they are not the same.

### Conversation History

Example:

```text
User:
"My name is Rahul."

Agent:
"Nice to meet you."

User:
"I am learning AI."

Agent:
"That's great."
```

The complete sequence of messages is the conversation history.

```text
Message 1
Message 2
Message 3
Message 4
...
```

### Agent Memory

A memory system may extract only useful information:

```text
User name = Rahul
Interest = AI
```

Instead of storing or retrieving every message.

### Comparison

| Conversation History | Agent Memory |
|---|---|
| Record of conversation messages | Selected useful information |
| Usually chronological | Can be structured/retrieved |
| Can become very large | Can be selectively stored |
| Mainly provides conversational context | Provides persistent/relevant information |
| May be temporary | Can persist across sessions |

### Example

Suppose a user says:

```text
User:
"My name is Rahul.
I am studying AI.
Yesterday I watched a movie.
Today I am learning RAG."
```

Conversation history contains everything.

Memory might retain:

```text
Name = Rahul
Interest = AI / RAG
```

The movie statement may not be relevant later.

### Important Distinction

Do not think:

```text
Memory = Entire Chat History
```

Instead:

```text
Conversation History
        ↓
Select / Summarize / Extract
        ↓
Relevant Information
        ↓
Memory
        ↓
Retrieve when needed
        ↓
Current Context
```

### Key Point

> **Conversation history is the record of what was said, while agent memory is a mechanism for storing and retrieving information that is useful beyond the immediate conversation context.**

### Interview Answer

> **Conversation history is the chronological record of messages exchanged between the user and the system. Agent memory is a mechanism that stores and retrieves selected information that may be useful later. Memory does not necessarily contain the entire conversation; it focuses on relevant information that can be persisted and retrieved when needed.**

## 4. What is short-term vs long-term memory?

### Answer

The difference is mainly based on **how long the information is maintained and how it is used**.

### Short-Term Memory

Short-term memory contains information needed during the **current conversation or current task**.

For example:

```text
User:
"Find a laptop under ₹60,000."

Agent:
Finds Laptop A.

User:
"Compare it with Laptop B."

```

The agent needs to remember:

```text
Laptop A
Price
Specifications
```

while completing the current task.

### Short-Term Memory Flow

```text
Current Task
     ↓
Current State / Context
     ↓
Tool Calls
     ↓
Intermediate Results
     ↓
Final Answer
```

Short-term memory is often closely related to the agent's current state and active context.

---

### Long-Term Memory

Long-term memory stores information that may remain useful across **multiple conversations or sessions**.

For example:

```text
User preference:
"Prefers laptops with 16 GB RAM."
```

This information could potentially be useful in future sessions.

### Long-Term Memory Flow

```text
Conversation
     ↓
Important Information
     ↓
Persistent Storage
     ↓
Future Session
     ↓
Retrieve Relevant Memory
     ↓
Current Context
```

### Comparison

| Short-Term Memory | Long-Term Memory |
|---|---|
| Used for current task/conversation | Used across sessions/tasks |
| Usually temporary | Usually persistent |
| Contains current state and intermediate results | Contains selected useful information |
| Helps continue the current workflow | Helps personalize or inform future tasks |
| Often stored in active state/context | Often stored in persistent storage |

### Example

```text
Short-Term:
Current order = Order #123
Payment status = Pending

Long-Term:
User prefers vegetarian meals.
```

The order status is relevant to the current task, while the preference may remain useful in future tasks.

### Important Point

Long-term memory should still be **selectively retrieved**.

It does not mean:

```text
Store everything
     ↓
Send everything to LLM
```

Instead:

```text
Stored Memory
     ↓
Retrieve relevant information
     ↓
Current Context
     ↓
LLM
```

### Key Point

> **Short-term memory supports the current task or conversation, while long-term memory stores useful information that can persist across sessions and be retrieved when relevant.**

### Interview Answer

> **Short-term memory contains information required for the current conversation or task, such as intermediate tool results and current state. Long-term memory stores selected information that can persist across sessions, such as useful user preferences or previous task information. Both should be selectively retrieved rather than blindly included in every prompt.**

## 5. How can an agent maintain state across multiple tool calls?

### Answer

An agent maintains state by keeping a **shared state object** that is updated after each action or tool call.

For example, suppose an agent needs to:

1. Search for a product
2. Get its price
3. Calculate the total

The state can evolve as follows.

### Initial State

```text
{
    user_request: "Find laptop price and total for 3 units",
    product: null,
    price: null,
    quantity: 3,
    total: null
}
```

### After Tool 1

```text
product_search()
```

State becomes:

```text
{
    user_request: "...",
    product: "Laptop A",
    price: 50000,
    quantity: 3,
    total: null
}
```

### After Tool 2

```text
calculator(50000 * 3)
```

State becomes:

```text
{
    user_request: "...",
    product: "Laptop A",
    price: 50000,
    quantity: 3,
    total: 150000
}
```

Now the agent has enough information to answer.

### General Flow

```text
             ┌─────────────┐
             │    State    │
             └──────┬──────┘
                    ↓
                   LLM
                    ↓
                 Tool 1
                    ↓
              Update State
                    ↓
                   LLM
                    ↓
                 Tool 2
                    ↓
              Update State
                    ↓
                   LLM
                    ↓
              Final Answer
```

### Ways to Maintain State

Depending on the application, state can be stored in:

- In-memory objects
- Databases
- Key-value stores
- Agent framework state stores
- Persistent storage

For short-running tasks:

```text
Application Memory
```

may be enough.

For long-running tasks:

```text
Database / Persistent Store
```

may be required.

### State Should Be Structured

Instead of storing everything as one large text block:

```text
"User said this... then tool returned this..."
```

it is often better to maintain structured state:

~~~json
{
  "user_id": "123",
  "task": "product_purchase",
  "product": "Laptop A",
  "price": 50000,
  "quantity": 3,
  "payment_status": "pending"
}
~~~

This makes state easier to update and retrieve.

### Key Point

> **An agent can maintain state across tool calls by keeping a shared, structured state that is updated with tool results and passed to the next decision step.**

### Interview Answer

> **An agent can maintain state by using a shared state object that stores the user's goal, intermediate results, previous actions, and current progress. After every tool call, the tool result updates this state, and the updated state is used by the LLM to decide the next action. For long-running tasks, the state can be persisted in a database or other storage system.**

## 6. What problems can occur when too much conversation history is passed to an LLM?

### Answer

Passing the entire conversation history to the LLM can create several problems.

### 1. Context Window Limit

LLMs have a limited context window.

If the conversation becomes very large:

```text
Huge Conversation
       ↓
Context Window
       ↓
Limit exceeded
```

The request may fail or older information may need to be removed.

---

### 2. Higher Cost

More input tokens generally mean more token usage.

```text
More History
     ↓
More Input Tokens
     ↓
Higher Cost
```

This becomes especially important for agents that make multiple LLM calls.

---

### 3. Higher Latency

Sending a large amount of context takes more processing.

```text
Large Context
     ↓
More Processing
     ↓
Higher Latency
```

---

### 4. Irrelevant Information

Old messages may no longer be relevant.

Example:

```text
Conversation contains:

100 messages about weather
+
1 message about current database task
```

Sending everything can make it harder to focus on the current task.

---

### 5. Conflicting Information

Old information may conflict with newer information.

Example:

```text
Old:
User prefers Python.

Later:
User now wants C++.
```

If both are passed without proper context handling, the LLM may become confused about which information is current.

---

### 6. Reduced Attention to Important Information

When too much information is included, important details can become harder for the model to use effectively.

Instead of:

```text
Relevant Context
```

the model receives:

```text
Relevant Context
+
Old Messages
+
Irrelevant Messages
+
Repeated Information
+
Tool Logs
+
Unnecessary Details
```

This can reduce the usefulness of the context.

---

### 7. Repeated Tool Results

Agent conversations can contain large tool outputs.

For example:

```text
Search Result 1
Search Result 2
Search Result 3
Database Result
API Result
...
```

Passing all of these repeatedly can unnecessarily increase context size.

### Better Approach

Instead of:

```text
Entire Conversation
        ↓
      LLM
```

use:

```text
Conversation / History
        ↓
Summarize / Filter / Retrieve
        ↓
Relevant Context
        ↓
      LLM
```

Possible techniques include:

- Conversation summarization
- Context selection
- Retrieval of relevant history
- Structured state
- Memory retrieval
- Removing redundant tool outputs
- Keeping only recent messages when appropriate

### Example

Instead of passing:

```text
100 previous messages
```

the system may construct:

```text
Current Task:
Book flight to Delhi

Relevant State:
Date = 10 October
Flight = AI-302
Payment = Pending

Relevant Memory:
User prefers window seat.
```

Then provide only this relevant context to the LLM.

### Key Point

> **Passing too much conversation history can increase token usage, cost, latency, and context-window pressure while introducing irrelevant or conflicting information. Good agent systems select, summarize, or retrieve relevant context instead of blindly passing the entire history.**

### Interview Answer

> **Passing too much conversation history can cause context-window problems, higher token cost, higher latency, and reduced relevance. Old or conflicting information can also confuse the model, especially in long-running agent workflows. Instead of sending the entire history, we should maintain structured state and selectively retrieve, summarize, or filter the information relevant to the current task.**
