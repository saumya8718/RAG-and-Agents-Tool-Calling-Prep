# 03. Agent Loop & Reasoning

## 1. What is the agent loop?

### Answer

The **agent loop** is the repeated process through which an AI agent:

1. Understands the current goal or state
2. Decides what action to take
3. Executes the action or calls a tool
4. Observes the result
5. Decides what to do next
6. Repeats until the task is complete

### Basic Agent Loop

```text
User Goal
    ↓
   LLM
    ↓
Decide Action
    ↓
Execute Action / Tool
    ↓
Observe Result
    ↓
Update State
    ↓
   LLM
    ↓
Decide Next Action
    ↓
   ...
    ↓
Final Answer
```

### Example

User asks:

> "Find the price of a laptop and calculate the cost for 3 laptops."

The agent may perform:

```text
Understand Goal
      ↓
Search for laptop price
      ↓
Get price = ₹50,000
      ↓
Decide calculation is needed
      ↓
Calculator: 50,000 × 3
      ↓
Get result = ₹1,50,000
      ↓
Return final answer
```

The important part is that the agent does not necessarily know the complete sequence beforehand. It can use the result of one step to decide what to do next.

### Agent Loop vs Simple LLM Call

Simple LLM application:

```text
Input → LLM → Output
```

Agent:

```text
Goal
 ↓
LLM
 ↓
Action
 ↓
Result
 ↓
LLM
 ↓
Action
 ↓
Result
 ↓
Final Answer
```

### Key Point

> **The agent loop is the repeated cycle of deciding, acting, observing the result, and deciding again until the task is completed or the execution is stopped.**

### Interview Answer

> **An agent loop is the execution cycle of an AI agent. The agent understands the goal, decides on an action, executes a tool or action, observes the result, updates its state, and then decides what to do next. This continues until the agent reaches a stopping condition.**

## 2. How does an agent decide when to stop?

### Answer

An agent can stop when it determines that the **user's goal has been completed** or when a predefined execution limit or failure condition is reached.

Common stopping conditions include:

### 1. Task Completed

The agent has obtained enough information and can provide the final answer.

```text
Goal
 ↓
Action
 ↓
Result
 ↓
Goal satisfied
 ↓
Final Answer
```

Example:

```text
User: "What is 20 × 5?"

Agent
 ↓
Calculator
 ↓
100
 ↓
Task complete
 ↓
Answer: 100
```

---

### 2. LLM Produces a Final Answer

The LLM may determine that no additional tool calls are necessary.

```text
LLM
 ↓
No more tools needed
 ↓
Final Response
```

---

### 3. Maximum Step Limit Reached

The system can impose a maximum number of actions.

```text
Maximum steps = 10

Step 1
Step 2
Step 3
...
Step 10
 ↓
Stop
```

This prevents the agent from running indefinitely.

---

### 4. Error or Failure

The agent may stop if an unrecoverable error occurs.

For example:

```text
Tool Call
 ↓
API unavailable
 ↓
Retry
 ↓
Still failing
 ↓
Stop
```

---

### 5. Timeout or Resource Limit

The system may stop the agent when:

- Time limit is reached
- Token limit is reached
- Cost limit is reached
- External service limit is reached

### Practical Stopping Logic

```text
          ┌──────────────┐
          │ Agent Action │
          └──────┬───────┘
                 ↓
          Observe Result
                 ↓
       Is task completed?
            /          \
          Yes           No
           ↓             ↓
     Final Answer    More Steps?
                         / \
                       Yes  No
                        ↓    ↓
                 Continue   Stop
```

### Key Point

> **An agent normally stops when the task is complete, no further action is needed, or a safety/resource limit such as maximum steps, timeout, or cost limit is reached.**

### Interview Answer

> **An agent decides to stop when it determines that the task has been completed and no more tool calls are necessary. In production, stopping should also be controlled by limits such as maximum steps, timeouts, token or cost limits, and failure conditions to prevent endless execution.**

## 3. What happens when an agent needs to call multiple tools?

### Answer

When an agent needs multiple tools, it can perform **multiple tool calls as part of the same agent loop**.

The result of one tool call can influence the next decision.

### Example

User asks:

> "Find the price of a laptop and convert the price from USD to INR."

Suppose the agent has:

```text
product_search()
currency_converter()
```

The agent can execute:

```text
User Request
     ↓
LLM
     ↓
product_search()
     ↓
Product Price = $1000
     ↓
LLM
     ↓
currency_converter()
     ↓
₹83,000
     ↓
LLM
     ↓
Final Answer
```

### Important

The agent does not necessarily call all tools blindly.

Instead:

```text
Tool 1 Result
     ↓
LLM
     ↓
Decide whether another tool is needed
     ↓
Tool 2
     ↓
Result
     ↓
LLM
```

This makes tool usage dynamic.

### Multiple Tools in Sequence

```text
Goal
 ↓
Tool A
 ↓
Result A
 ↓
Tool B
 ↓
Result B
 ↓
Tool C
 ↓
Result C
 ↓
Final Answer
```

For example:

```text
Search
 ↓
Database Query
 ↓
Calculator
 ↓
Final Response
```

### Parallel Tool Calls

In some systems, independent tools can potentially be executed in parallel.

For example:

```text
              ┌→ Weather API
User → LLM ───┤
              └→ News API
```

If neither tool depends on the result of the other, parallel execution can reduce latency.

But if Tool B needs the output of Tool A:

```text
Tool A
  ↓
Result A
  ↓
Tool B
```

they must be executed sequentially.

### Key Point

> **When multiple tools are needed, the agent can call them one after another, using previous results to decide the next action. Independent tool calls may also be executed in parallel when supported.**

### Interview Answer

> **When an agent needs multiple tools, it can perform multiple tool calls within its agent loop. The result of one tool can be given back to the LLM, which decides whether another tool is required. Dependent calls are usually sequential, while independent calls can sometimes be executed in parallel to reduce latency.**

## 4. What is multi-step reasoning in an agent?

### Answer

**Multi-step reasoning** means solving a task through a sequence of intermediate actions or decisions rather than trying to produce the final result in a single step.

For example:

> "Find the price of a phone, calculate the price after a 10% discount, and convert it to INR."

This requires several steps:

```text
Step 1: Find phone price
        ↓
Step 2: Calculate 10% discount
        ↓
Step 3: Calculate discounted price
        ↓
Step 4: Convert to INR
        ↓
Step 5: Generate final answer
```

The important idea is that the output of one step can become the input for the next step.

### Example

Suppose:

```text
Product price = $1000
```

The agent may do:

```text
Product Search
      ↓
$1000
      ↓
Discount Calculator
      ↓
$900
      ↓
Currency Converter
      ↓
₹74,700
      ↓
Final Answer
```

### Multi-Step vs Single-Step

Single-step:

```text
Question → LLM → Answer
```

Multi-step:

```text
Question
   ↓
Action 1
   ↓
Result 1
   ↓
Action 2
   ↓
Result 2
   ↓
Action 3
   ↓
Final Answer
```

### Why Is It Useful?

It allows an agent to handle tasks that involve:

- Multiple tools
- Intermediate results
- Conditional decisions
- Complex workflows
- Information gathering
- Calculations

### Important Distinction

Multi-step reasoning does not necessarily mean exposing the model's private chain-of-thought.

For an interview, focus on the **observable execution process**:

```text
Goal
 ↓
Action
 ↓
Observation
 ↓
Next Action
 ↓
Final Result
```

### Key Point

> **Multi-step reasoning in an agent means solving a task through multiple intermediate decisions and actions, where previous results can influence subsequent actions.**

### Interview Answer

> **Multi-step reasoning means that an agent does not solve a task in one operation. It breaks the task into multiple actions or decisions, uses the result of one step to determine the next step, and continues until it reaches the final result.**

## 5. What causes an agent to enter an infinite loop?

### Answer

An agent can enter an **infinite loop** when it repeatedly performs the same or similar actions without reaching a valid stopping condition.

### Example

```text
LLM
 ↓
Search Tool
 ↓
Result
 ↓
LLM
 ↓
Search Tool
 ↓
Result
 ↓
LLM
 ↓
Search Tool
 ↓
...
```

The agent keeps repeating the same action.

### Major Causes

#### 1. No Clear Stopping Condition

If the agent does not know when the task is complete:

```text
Task
 ↓
Action
 ↓
Action
 ↓
Action
 ↓
...
```

---

#### 2. Poor Tool Results

If a tool continuously returns incomplete or unexpected information, the agent may keep trying.

```text
Tool
 ↓
Incomplete Result
 ↓
LLM retries
 ↓
Incomplete Result
 ↓
LLM retries
 ↓
...
```

---

#### 3. Repeated Tool Selection

The LLM may repeatedly select the same tool because it incorrectly believes another attempt is necessary.

---

#### 4. Incorrect State Management

If the agent does not properly track what has already been done, it may repeat previous actions.

```text
Search completed
      ↓
State not updated
      ↓
Agent thinks search is still required
      ↓
Search again
```

---

#### 5. Tool Failure

A failed tool call can cause repeated retries if retries are not limited.

```text
Tool fails
 ↓
Retry
 ↓
Tool fails
 ↓
Retry
 ↓
...
```

### How to Prevent Infinite Loops

Use:

- Maximum step count
- Timeouts
- Retry limits
- Clear stopping conditions
- State tracking
- Duplicate-action detection
- Tool error handling
- Human approval for sensitive operations

### Example

```text
max_steps = 10

while not finished and steps < max_steps:
    choose_action()
    execute_action()
    observe_result()
    steps += 1
```

If:

```text
steps == 10
```

the system stops the agent.

### Key Point

> **Infinite loops usually occur because the agent cannot reach or recognize a stopping condition, repeatedly selects the same action, receives poor tool results, or has incorrect state/error handling.**

### Interview Answer

> **An agent can enter an infinite loop when it repeatedly performs actions without making progress. Common causes include missing stopping conditions, repeated tool selection, incorrect state tracking, continuously failing tools, and unlimited retries. Maximum step limits, timeouts, retry limits, and proper state tracking can prevent this.**

## 6. How do you limit the number of agent steps?

### Answer

The simplest approach is to define a **maximum number of steps** that the agent is allowed to execute.

For example:

```text
Maximum steps = 5
```

The agent can execute at most:

```text
Step 1
Step 2
Step 3
Step 4
Step 5
```

After that, execution stops.

### Basic Logic

```text
steps = 0
max_steps = 5

while task_not_complete and steps < max_steps:

    choose_action()

    execute_action()

    observe_result()

    steps += 1
```

When:

```text
steps >= max_steps
```

the agent stops.

### Other Limits

Maximum steps should usually be combined with other controls.

#### 1. Timeout

Stop execution after a specific amount of time.

```text
Maximum execution time = 30 seconds
```

#### 2. Token Limit

Limit the amount of LLM processing.

```text
Maximum tokens = 10,000
```

#### 3. Cost Limit

Prevent excessive API spending.

```text
Maximum cost = ₹X
```

#### 4. Tool-Specific Limits

Some tools can have their own limits.

For example:

```text
Search API:
Maximum calls = 3
```

#### 5. Retry Limit

Prevent repeated failed tool calls.

```text
Maximum retries = 2
```

### Example

A production agent could have:

```text
Max steps      = 10
Max retries    = 2
Timeout        = 60 seconds
Max tool calls = 8
```

If any important limit is reached:

```text
Agent
 ↓
Limit reached
 ↓
Stop safely
 ↓
Return result/error
```

### Why Are Limits Important?

They protect against:

- Infinite loops
- Excessive API usage
- High costs
- Long response times
- Repeated failed actions
- Uncontrolled tool execution

### Key Point

> **Agent execution should be bounded using maximum steps, timeouts, retry limits, token limits, cost limits, and tool-specific limits.**

### Interview Answer

> **I would limit an agent using a maximum step count as the primary control. I would also add timeouts, retry limits, token or cost limits, and tool-specific limits. If any limit is reached, the agent should stop safely instead of continuing indefinitely.**

## 7. What is the difference between deterministic workflows and agentic workflows?

### Answer

The main difference is **how the next step is selected**.

### Deterministic Workflow

A deterministic workflow follows a **predefined sequence of steps**.

The developer decides the execution path.

```text
Input
 ↓
Step 1
 ↓
Step 2
 ↓
Step 3
 ↓
Output
```

For example:

```text
User Question
      ↓
Create Embedding
      ↓
Search Vector DB
      ↓
Retrieve Documents
      ↓
LLM
      ↓
Answer
```

The sequence is known in advance.

### Agentic Workflow

An agentic workflow allows the LLM/agent to **dynamically decide what action should happen next**.

```text
Goal
 ↓
LLM
 ↓
Choose Action
 ↓
Tool
 ↓
Observe Result
 ↓
LLM
 ↓
Choose Next Action
 ↓
...
 ↓
Final Answer
```

The path can change depending on the task and intermediate results.

### Example

Suppose the user asks:

> "Research a company and give me a summary."

A deterministic workflow might always do:

```text
Search
 ↓
Retrieve
 ↓
Summarize
```

An agentic workflow might do:

```text
Search
 ↓
Read Result
 ↓
Need more information?
    /       \
  Yes       No
   ↓         ↓
Search 2   Summarize
   ↓
Compare Results
   ↓
Summarize
```

The agent decides what happens next.

### Comparison

| Deterministic Workflow | Agentic Workflow |
|---|---|
| Predefined execution path | Dynamic execution path |
| Developer controls sequence | LLM/agent can choose next action |
| More predictable | More flexible |
| Easier to test | More difficult to test |
| Easier to debug | More difficult to debug |
| Usually more controlled | Requires stronger guardrails |
| Good for fixed processes | Good for dynamic tasks |

### When to Use Each?

#### Deterministic Workflow

Use when:

```text
Steps are known
+
Process is predictable
+
Strong control is required
```

Examples:

- Data pipelines
- Fixed RAG pipelines
- ETL processes
- Form processing

#### Agentic Workflow

Use when:

```text
Steps are not completely known
+
Tool selection is dynamic
+
Intermediate results affect next actions
```

Examples:

- Research assistants
- Complex troubleshooting
- Multi-tool tasks
- Dynamic information gathering

### Important Point

Agentic does **not automatically mean better**.

If a task can be solved reliably with a fixed workflow, introducing an agent can add unnecessary complexity.

### Key Point

> **A deterministic workflow follows a predefined execution path, while an agentic workflow dynamically chooses the next action based on the goal, current state, available tools, and intermediate results.**

### Interview Answer

> **A deterministic workflow has a predefined sequence of steps controlled by the developer, so its execution is predictable. An agentic workflow allows the agent to dynamically select the next action based on the task and intermediate results. Deterministic workflows are easier to control and debug, while agentic workflows provide more flexibility for dynamic, multi-step tasks.**
