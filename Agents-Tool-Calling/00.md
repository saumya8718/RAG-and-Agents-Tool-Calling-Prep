# Agents / Tool Calling

Agents and Tool Calling are an extension of LLM applications where the model can not only generate text, but also decide when it needs to take an action using an external tool.

This section focuses on understanding how AI agents work, how LLMs interact with tools, how agents maintain state, and how to build reliable agentic systems.

## Why Learn Agents and Tool Calling?

Agents are useful when an application needs to:

- Perform multiple steps to complete a task
- Interact with external APIs
- Query databases
- Search for information
- Perform calculations
- Use RAG as a tool
- Make decisions based on tool results
- Automate complex workflows

## Basic Agent Flow

~~~text
User Goal
    ↓
    LLM
    ↓
Decide Action
    ↓
Tool Call
    ↓
Tool Result
    ↓
    LLM
    ↓
Decide Next Action
    ↓
    ...
    ↓
Final Answer
~~~

## Agents / Tool Calling Interview Roadmap

### 1. Agent Fundamentals

- What is an AI agent?
- How is an AI agent different from a traditional LLM application?
- What are the main components of an AI agent?
- How does an agent decide what action to take?
- What is the difference between an LLM, workflow, and agent?
- When should you use an agent instead of a normal LLM pipeline?
- What are the major limitations and failure modes of AI agents?

### 2. Tools & Tool Calling

- What is a tool in an AI agent?
- What is tool calling/function calling?
- Why can't an LLM directly execute a function?
- How does an LLM decide which tool to call?
- What information should a tool definition/schema contain?
- What is structured tool input/output?
- How does a complete tool-calling flow work?
- What happens if the LLM generates invalid tool arguments?
- Function calling vs traditional API calling

### 3. Agent Loop & Reasoning

- What is the agent loop?
- How does an agent decide when to stop?
- What happens when an agent needs to call multiple tools?
- What is multi-step reasoning in an agent?
- What causes an agent to enter an infinite loop?
- How do you limit the number of agent steps?
- Deterministic workflows vs agentic workflows

### 4. Memory & State

- What is memory in an AI agent?
- Why does an agent need state?
- Conversation history vs agent memory
- Short-term vs long-term memory
- Maintaining state across multiple tool calls
- Problems caused by too much conversation history

### 5. Multi-Agent Systems

- What is a multi-agent system?
- When would you use multiple agents instead of one?
- How can multiple agents communicate?
- Advantages and problems of multi-agent architectures
- How can one agent delegate tasks to specialized agents?

### 6. Agent Frameworks & Architecture

- What is LangChain?
- What is LangGraph?
- Chain vs workflow vs agent
- What is a state graph?
- When should you avoid an agent framework?
- How would you implement a simple tool-calling agent without LangChain/LangGraph?

### 7. Agent + RAG + Tools

- How can an agent use RAG as a tool?
- RAG pipeline vs an agent that can perform retrieval
- How does an agent decide whether to retrieve or answer directly?
- How can an agent combine multiple tools?
- How would you design a research agent using multiple sources?

### 8. Reliability, Security & Guardrails

- What can go wrong when an LLM is allowed to call tools?
- How do you validate tool arguments?
- How do you prevent unauthorized actions?
- What is prompt injection in an agentic system?
- Why are tool outputs potentially untrusted?
- How would you safely give an agent access to a database or API?
- How do you handle tool failures, timeouts, retries, and malformed responses?

## Learning Goal

By the end of this section, you should be able to:

1. Explain what an AI agent is.
2. Explain how tool calling works.
3. Understand the agent loop.
4. Explain state and memory in agents.
5. Design simple tool-calling agents.
6. Understand how agents can use RAG and multiple tools.
7. Explain common agent failure modes.
8. Discuss security, reliability, and guardrails.
9. Explain the role of frameworks such as LangChain and LangGraph.
10. Design a basic production-ready agent architecture.
