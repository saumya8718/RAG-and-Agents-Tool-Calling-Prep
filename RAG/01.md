# 01 — RAG Fundamentals

## 1. What is RAG and why is it used?

### What is RAG?

**RAG (Retrieval-Augmented Generation)** is a technique that combines **information retrieval** with a **Large Language Model (LLM)**.

Instead of relying only on the knowledge stored in the LLM, RAG first **retrieves relevant information from an external knowledge source** and provides that information to the LLM as context. The LLM then uses this context to generate the answer.

### Basic RAG Flow

```text
User Query
    ↓
Query Processing
    ↓
Retrieve Relevant Documents
    ↓
Relevant Context
    ↓
LLM
    ↓
Generated Answer
```

### Why is RAG used?

RAG is used when an LLM needs access to:

- Private or domain-specific information
- Frequently changing information
- Large document collections
- External knowledge bases
- Enterprise data

### Example

Suppose a company has thousands of internal documents and an employee asks:

> "What is our company's leave policy for interns?"

A general LLM may not have access to this private company information.

With RAG:

```text
User Question
      ↓
Search Company Documents
      ↓
Retrieve Relevant Document
      ↓
Provide Retrieved Information to LLM
      ↓
LLM Generates Answer
```

The LLM can then generate an answer using the relevant company document as context.

### Key Point

> **RAG = Retrieval + Context + Generation**

RAG allows an LLM to use **external knowledge** while generating a response.

### Interview Answer

> **RAG, or Retrieval-Augmented Generation, is an approach that combines information retrieval with a Large Language Model. It retrieves relevant information from an external knowledge source and provides it to the LLM as context before generating an answer. RAG is used to enable LLMs to work with private, domain-specific, frequently changing, or large external datasets.**

 
## 2. What problem does RAG solve that a standalone LLM cannot?

### Answer

A **standalone LLM** can generate answers using the knowledge it learned during training, but it does not automatically have access to **private, domain-specific, or frequently updated external information**.

RAG solves this problem by allowing the LLM to **retrieve relevant information from an external knowledge source** and use it as context while generating the answer.

### Problems with a Standalone LLM

A standalone LLM may face the following limitations:

- **No access to private data**  
  It cannot automatically access a company's internal documents, databases, or knowledge base.

- **Knowledge can become outdated**  
  Information that changes after the model's training may not be available to the LLM.

- **Limited access to domain-specific information**  
  The model may not know specific information about a particular organization, product, or internal process.

- **Hallucination risk**  
  When the required information is unavailable, the model may generate an answer that sounds correct but is not supported by the actual data.

### How RAG Solves This

RAG adds a retrieval step before generation:

```text
Standalone LLM:

User Query
    ↓
LLM
    ↓
Answer


RAG:

User Query
    ↓
Retriever
    ↓
Relevant External Information
    ↓
LLM + Retrieved Context
    ↓
Grounded Answer
```

The retrieved information gives the LLM **relevant external context** that it can use to generate the response.

### Example

Consider an organization's internal HR documents.

User asks:

> "How many paid leaves can an employee take according to our current company policy?"

A standalone LLM may not know the company's current policy.

With RAG:

```text
User Question
      ↓
Search HR Documents
      ↓
Retrieve Current Leave Policy
      ↓
Pass Relevant Information to LLM
      ↓
Generate Answer
```

The answer can therefore be based on the organization's actual documents.

### Key Point

> **A standalone LLM relies primarily on its learned knowledge, whereas RAG allows the LLM to retrieve and use relevant external information at query time.**

### Interview Answer

> **RAG solves the limitation of standalone LLMs that they cannot automatically access private, domain-specific, or frequently updated external information. RAG retrieves relevant information from an external knowledge source and provides it to the LLM as context, allowing the model to generate a more relevant and grounded response.**


## 3. How does a basic RAG pipeline work?

### Answer

A basic RAG pipeline works by **retrieving relevant information from an external knowledge source and providing it to an LLM as context** before generating the final answer.

The basic flow is:

```text
User Query
    ↓
Query Processing
    ↓
Retrieval
    ↓
Relevant Documents / Chunks
    ↓
Context Construction
    ↓
LLM
    ↓
Generated Answer
```

### Step-by-Step Process

#### 1. User Query

The process starts when the user asks a question.

**Example:**

> "What is the company's leave policy for interns?"

---

#### 2. Query Processing

The user's query is processed so that it can be used to search the external knowledge source.

---

#### 3. Retrieval

The system searches the available knowledge source and retrieves information that is relevant to the user's query.

The knowledge source can contain:

- Documents
- PDFs
- Web pages
- Databases
- Company knowledge bases

---

#### 4. Retrieve Relevant Documents / Chunks

Instead of sending the entire knowledge base to the LLM, RAG selects the **most relevant documents or chunks** related to the query.

```text
Knowledge Base
 ├── Document 1
 ├── Document 2  ← Relevant
 ├── Document 3
 ├── Document 4  ← Relevant
 └── Document 5
```

---

#### 5. Context Construction

The retrieved information is combined into a context that can be provided to the LLM.

```text
User Query
    +
Retrieved Information
    ↓
Context
```

---

#### 6. LLM Generation

The LLM receives the user's query along with the retrieved context and generates the final answer.

```text
Query + Retrieved Context
          ↓
         LLM
          ↓
    Final Answer
```

### Complete Example

```text
User:
"What is the company's leave policy for interns?"
          ↓
Query Processing
          ↓
Search Knowledge Base
          ↓
Retrieve Relevant Leave Policy
          ↓
Construct Context
          ↓
Send Query + Context to LLM
          ↓
Generate Answer
```

### Key Point

> **A basic RAG pipeline first retrieves relevant information from an external knowledge source, then provides that information as context to an LLM, which uses the context to generate the final answer.**

### Interview Answer

> **A basic RAG pipeline starts with a user query. The system processes the query and retrieves relevant documents or chunks from an external knowledge source. These retrieved results are then used to construct the context for the LLM. The LLM receives the user query along with the retrieved context and generates the final answer.**


## 4. What are the main components of a RAG system?

### Answer

A RAG system consists of several components that work together to retrieve relevant information and use it to generate an answer.

The main components are:

```text
Documents / Knowledge Base
          ↓
Document Processing
          ↓
Chunking
          ↓
Embedding Model
          ↓
Vector Database / Index
          ↓
Retriever
          ↓
Relevant Documents / Chunks
          ↓
Context Construction
          ↓
LLM
          ↓
Generated Answer
```

### 1. Knowledge Source

The knowledge source contains the information that the RAG system will retrieve from.

Examples include:

- PDFs
- Documents
- Web pages
- Databases
- Company knowledge bases

---

### 2. Document Processing

The documents are processed before they are stored.

This may include:

- Extracting text
- Cleaning the text
- Removing unnecessary content
- Preparing the documents for chunking

---

### 3. Chunking

Large documents are divided into smaller pieces called **chunks**.

```text
Large Document
      ↓
 ┌────┬────┬────┬────┐
 │ C1 │ C2 │ C3 │ C4 │
 └────┴────┴────┴────┘
```

Chunking makes it easier to retrieve only the relevant parts of a document.

---

### 4. Embedding Model

An embedding model converts text into **numerical vectors**.

```text
Text
 ↓
Embedding Model
 ↓
Vector
```

These vectors represent the semantic meaning of the text and are used for similarity-based retrieval.

---

### 5. Vector Database / Index

The embeddings of document chunks are stored in a vector database or vector index.

It allows the system to efficiently search for chunks that are semantically similar to the user's query.

---

### 6. Retriever

The retriever takes the user's query and searches the knowledge base to find the most relevant documents or chunks.

```text
User Query
    ↓
Retriever
    ↓
Relevant Chunks
```

---

### 7. Context Construction

The retrieved chunks are combined with the user's query to create the context that will be provided to the LLM.

```text
User Query
     +
Retrieved Chunks
     ↓
Context
```

---

### 8. LLM

The LLM receives the user's query along with the retrieved context and generates the final answer.

```text
Query + Context
      ↓
     LLM
      ↓
Final Answer
```

---

### Summary

| Component | Main Purpose |
|---|---|
| Knowledge Source | Stores the information |
| Document Processing | Prepares documents |
| Chunking | Divides documents into smaller pieces |
| Embedding Model | Converts text into vectors |
| Vector Database / Index | Stores and searches vectors |
| Retriever | Finds relevant information |
| Context Construction | Prepares retrieved information for the LLM |
| LLM | Generates the final answer |

### Key Point

> **The main components of a RAG system are the knowledge source, document processing and chunking, embedding model, vector database/index, retriever, context construction, and LLM.**

### Interview Answer

> **A RAG system mainly consists of a knowledge source, document processing and chunking, an embedding model, a vector database or index, a retriever, context construction, and an LLM. Documents are processed and divided into chunks, converted into embeddings, and stored in a vector database. When a user asks a question, the retriever finds relevant chunks, which are provided to the LLM as context to generate the final answer.**


## 5. RAG vs Fine-tuning — When would you use each?

### Answer

**RAG and fine-tuning solve different problems.**

- **RAG** gives an LLM access to external information at query time.
- **Fine-tuning** changes the model's behavior by training it further on a specific dataset.

### RAG

RAG is useful when the main requirement is to provide the LLM with **external or changing knowledge**.

Use RAG when:

- The information is stored in external documents or knowledge bases.
- The information changes frequently.
- You need the model to work with private or domain-specific documents.
- You want to retrieve specific information at query time.
- You need to update the knowledge base without retraining the model.

### Fine-tuning

Fine-tuning is useful when the main requirement is to **change or specialize the model's behavior**.

Use fine-tuning when:

- You want the model to follow a particular style or format.
- You want to specialize the model for a specific task.
- You need consistent behavior for a particular type of task.
- You have a suitable dataset for training the model further.

### RAG vs Fine-tuning

| Aspect | RAG | Fine-tuning |
|---|---|---|
| Main purpose | Provide external knowledge | Change model behavior |
| Knowledge | Retrieved at query time | Learned during additional training |
| Updating information | Update the knowledge source | Requires additional training |
| Private documents | Suitable | Can be used, but not the primary mechanism for retrieving documents |
| Changing response style | Limited | Suitable |
| Frequently changing data | Suitable | Less suitable |
| External knowledge retrieval | Yes | No |

### Simple Example

Suppose a company wants an AI assistant for its internal HR documents.

**If the goal is:**

> "Answer questions using our latest HR policies."

Use **RAG** because the system can retrieve the latest policy documents when answering.

**If the goal is:**

> "Make the model consistently respond in our company's specific format and style."

Fine-tuning may be appropriate because the goal is to change the model's behavior.

### Can RAG and Fine-tuning be used together?

Yes.

A system can use **fine-tuning to specialize the model's behavior** and **RAG to provide external knowledge**.

```text
Fine-tuning
     ↓
Specialized Model
     +
RAG
     ↓
External Knowledge
     ↓
Final Answer
```

### Key Point

> **Use RAG when you need to give the model access to external or changing information. Use fine-tuning when you need to specialize the model's behavior, style, or task performance.**

### Interview Answer

> **RAG and fine-tuning address different needs. RAG is preferred when the model needs access to external, private, domain-specific, or frequently changing information because the information can be retrieved at query time. Fine-tuning is preferred when the goal is to specialize the model's behavior, such as making it follow a particular style, format, or task. In some applications, both approaches can be used together.**


## 6. What are the advantages and limitations of RAG?

### Answer

RAG provides an LLM with relevant external information at query time. This makes it useful for applications that need access to private, domain-specific, or frequently changing information.

### Advantages of RAG

#### 1. Access to External Knowledge

RAG allows an LLM to use information from external knowledge sources such as:

- Documents
- Databases
- Knowledge bases
- Company data

---

#### 2. Works with Private and Domain-Specific Data

RAG can be used with information that is specific to an organization or domain.

**Example:**

A company's internal documents can be used to answer questions about its HR policies, products, or processes.

---

#### 3. Easier to Update Knowledge

When information changes, the knowledge source can be updated without necessarily retraining the LLM.

```text
Updated Document
      ↓
Knowledge Base
      ↓
Retriever
      ↓
LLM
      ↓
Updated Answer
```

---

#### 4. Reduces Dependence on the LLM's Stored Knowledge

Instead of depending only on the knowledge learned during model training, the LLM can use retrieved information from an external source.

---

#### 5. Better Grounding

Providing relevant retrieved information as context can help the generated answer stay connected to the available source material.

---

### Limitations of RAG

#### 1. Retrieval Quality Affects the Final Answer

If the retriever fails to find the correct information, the LLM may not have the required context to generate a good answer.

```text
Poor Retrieval
      ↓
Poor Context
      ↓
Poor Answer
```

---

#### 2. Chunking Can Affect Retrieval

Documents need to be divided into appropriate chunks.

If chunks are too small, important context may be lost.

If chunks are too large, retrieval may return unnecessary information.

---

#### 3. Additional System Complexity

A RAG system requires multiple components such as:

- Document processing
- Chunking
- Embeddings
- Vector database or index
- Retrieval
- Context construction
- LLM

This makes the system more complex than using an LLM alone.

---

#### 4. Latency

RAG introduces additional steps before the LLM generates an answer.

```text
Query
  ↓
Retrieval
  ↓
Context Construction
  ↓
LLM
  ↓
Answer
```

These additional operations can increase response time.

---

#### 5. Evaluation and Debugging Can Be Difficult

When a RAG system produces a poor answer, it can be difficult to determine whether the problem came from:

- Retrieval
- Chunking
- Embeddings
- Context construction
- LLM generation

---

### Advantages vs Limitations

| Advantages | Limitations |
|---|---|
| Access to external knowledge | Retrieval can fail |
| Works with private data | Requires good chunking |
| Easier knowledge updates | More system complexity |
| Reduces dependence on stored model knowledge | Can introduce additional latency |
| Can improve grounding | Evaluation and debugging can be difficult |

### Key Point

> **The main advantage of RAG is that it allows an LLM to use relevant external information without relying only on its stored knowledge. Its main limitations are retrieval quality, system complexity, latency, and the difficulty of evaluating and debugging the complete pipeline.**

### Interview Answer

> **RAG provides several advantages such as access to external and private knowledge, easier knowledge updates, and better grounding of LLM responses. However, its performance depends heavily on retrieval quality. Other limitations include chunking challenges, additional system complexity, latency, and difficulty in identifying whether a problem originates from retrieval or generation.**


## 7. What is the difference between RAG and simply providing a long context to an LLM?

### Answer

Both approaches provide additional information to an LLM, but they differ in **how the information is selected and provided**.

- **Long-context prompting** gives the LLM a large amount of information directly in the prompt.
- **RAG** first searches an external knowledge source and retrieves only the information relevant to the user's query.

### Long Context

In a long-context approach, the application may provide a large document or collection of information directly to the LLM.

```text
Large Amount of Information
          ↓
         LLM
          ↓
       Answer
```

The model has to process the provided information to find what is relevant.

---

### RAG

In RAG, the system first retrieves relevant information from an external knowledge source.

```text
User Query
    ↓
Retriever
    ↓
Relevant Information
    ↓
LLM
    ↓
Answer
```

Instead of providing the entire knowledge base, RAG attempts to provide the LLM with the most relevant information for the current query.

---

### RAG vs Long Context

| Aspect | RAG | Long Context |
|---|---|---|
| Information provided | Relevant retrieved information | Large amount of information |
| Selection | Retrieval system selects relevant content | Application provides the context |
| External knowledge source | Commonly used | Not necessarily required |
| Amount of context | Usually smaller and targeted | Can be very large |
| Retrieval step | Required | Not required |
| Knowledge updates | Can update the external knowledge source | Requires providing updated context |

### Example

Suppose a company has **10,000 documents**.

A long-context approach could provide a large collection of those documents to the LLM.

RAG instead works like:

```text
10,000 Company Documents
          ↓
       Retriever
          ↓
  Relevant 5–10 Chunks
          ↓
         LLM
          ↓
        Answer
```

The exact number of retrieved chunks depends on the system configuration.

### Key Point

> **Long-context prompting gives the LLM a large amount of information directly, while RAG retrieves relevant information from an external knowledge source and provides that retrieved information as context.**

### Interview Answer

> **The main difference is that long-context prompting provides a large amount of information directly to the LLM, whereas RAG uses a retrieval step to find relevant information from an external knowledge source before sending it to the LLM. RAG is therefore based on selective retrieval, while long-context prompting relies on providing a large context directly.**
